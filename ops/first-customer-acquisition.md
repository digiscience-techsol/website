# DigiScience First-Customer Acquisition Playbook

## Goal

Create a repeatable founder-led outbound motion for the first DigiScience customers without relying on fake case studies, fake logos, or generic AI agency messaging.

## First 30-Day Execution Rhythm

- Week 1: finalize proof assets, build first 50 target accounts, publish founder posts, start outreach to 25 prospects.
- Week 2: focus on AI Readiness Assessment outreach, run discovery calls, capture objections.
- Week 3: push industry-specific pilots for legal, manufacturing, and healthcare; publish blueprint-style posts; send second follow-ups.
- Week 4: send proposals, test partner/channel outreach, refine messaging, and decide the best-converting first offer.

## Tracker Usage

Use `assets/templates/digiscience-prospect-tracker.csv` as the manual tracker until CRM integration is implemented.

Every active prospect must have:

- Priority Offer
- Pain Hypothesis
- Trigger Event
- Lead Score
- Status
- Last Touch Date
- Next Follow-up Date
- Next Action

## Daily Tasks

- Publish or comment on one LinkedIn post.
- Send 10 targeted connection requests.
- Send 5 personalized messages.
- Send 2 follow-up emails.
- Update the prospect tracker.
- Review Hot and Warm leads.
- Schedule next actions.
- Capture objections.
- Improve one message.

## Weekly Review

Review:

- New prospects added
- Connection acceptance rate
- Replies
- Discovery calls booked
- Proposals requested
- Objections
- Best-performing offer
- Next week focus

## When to Create a Proposal

Create a proposal only when:

- The buyer has a clear workflow pain.
- A decision owner or sponsor is identified.
- The buyer accepts assessment, pilot, or governance review as a reasonable next step.
- Data, cloud, security, and stakeholder assumptions are documented.
- Timeline and commercial path are visible.

## When to Disqualify

Disqualify or move to Nurture when:

- There is no measurable workflow pain.
- The buyer only wants a generic chatbot demo.
- There is no sponsor, budget signal, or timeline.
- No sample data or system context can be discussed.
- The buyer rejects governance, human review, or security controls.

## How to Use the AI Readiness Offer

Use AI Readiness Assessment when:

- The buyer wants AI but does not know where to start.
- Multiple possible use cases exist.
- Data readiness is unknown.
- Governance or compliance risk is unclear.

Output should be a prioritized use case, readiness scorecard, governance gaps, and 45-day pilot recommendation.

## How to Use the 45-Day Pilot Offer

Use 45-Day Industry AI Pilot when:

- One workflow is visible.
- A business owner exists.
- Sample data can be prepared.
- Success criteria can be defined.
- Security/governance review can be included.

Output should be a controlled proof, reference architecture, governance controls, and scale/no-scale decision.
