# SharePoint CRM Integration Plan

Status: plan only. No Microsoft Graph secrets are committed and no SharePoint write integration is enabled yet.

## Objective

Extend the current `/api/lead` flow so every valid DigiScience lead is stored in Cloudflare KV and also written to a Microsoft SharePoint List for CRM-style follow-up.

Current source of truth until integration is active:

- Cloudflare Pages Function: `/api/lead`
- Cloudflare KV namespace: `DigiScience Leads`
- Binding: `LEADS_KV`
- Webhook notification: `LEAD_WEBHOOK_URL`

## Microsoft Graph Implementation Plan

1. Create or reuse a DigiScience-only Microsoft Entra app registration.
2. Grant the minimum required Graph permission for the SharePoint list write path.
3. Store the client secret only as a Cloudflare Pages secret.
4. Resolve and store `SHAREPOINT_SITE_ID` and `SHAREPOINT_LIST_ID` as Cloudflare environment variables.
5. Add a Graph token helper in the Cloudflare Pages Function.
6. After successful KV write, map the validated lead payload to SharePoint list fields.
7. If SharePoint write fails, keep the KV write and webhook path active, then include the CRM error in server-side logs only.
8. Return the same safe frontend response. Do not expose Graph error details to the browser.

## Cloudflare Pages Function Extension Design

Current flow:

1. Validate form payload.
2. Generate lead ID.
3. Calculate score and category.
4. Store in `LEADS_KV`.
5. Send webhook notification.
6. Return safe response.

Target flow:

1. Validate form payload.
2. Generate lead ID.
3. Calculate score, category and recommended action.
4. Store raw lead in `LEADS_KV`.
5. Write mapped CRM item to SharePoint through Microsoft Graph.
6. Send webhook notification including CRM write status.
7. Return safe response to browser.

## Safe Test Plan

1. Create a temporary SharePoint test list or test row flag.
2. Configure Cloudflare preview environment variables first.
3. Submit a test lead from a non-production preview URL.
4. Confirm KV write.
5. Confirm SharePoint list item creation.
6. Confirm webhook notification.
7. Confirm no secrets appear in logs or frontend responses.
8. Test Graph failure path by disabling one preview secret and confirming KV still works.
9. Promote variables to production only after preview passes.
